# Slot Design LMS

Самостоятельная LMS для курса «Слот-дизайн: от идеи до релиза». Один поток 15–25 участников, семь воскресений с 15 ноября 2026 в 15:00 CET. Интерфейс — английский; оплата отдельно, доступ выдаёт администратор. Подгрупп, тьютора и AI-проверки нет.

**Состояние на 2 ноября 2026:** LMS размещена на Hetzner: [временный HTTPS-адрес](https://lms-135-181-197-13.nip.io/). Пройдены 41 автотест и 8 групп сквозных серверных проверок на размещении. Адреса возврата Supabase Auth исправлены 2 ноября. Почта, контрольный вход по свежей ссылке, наполнение курса и полная приёмка ещё не завершены. [Эксплуатация и ограничения](docs/DEPLOYMENT.md).

## Передача и запуск на другом сервере

Начать с [инструкции получателю](docs/HANDOFF.md), затем пройти [установку на Linux](docs/SERVER-SETUP.md). В комплекте — шаблоны runtime/admin-настроек, проверка подключения, отдельные миграции, установка из Git, обновление и откат. Можно сохранить текущий Supabase или подготовить новый пустой проект. Данные и секреты передаются отдельно от Git.

## Возможности

- Вход по ссылке и паролю; участник, назначенный эксперт и администратор.
- Материалы модулей 0–7, расписание и сроки; в модуле 0 нет глоссария.
- Составные ДЗ 1.2–6.2, самооценки 6.1/7.1, итоговый пакет 7.2 и личный проект.
- Приватные черновики, файлы, неизменяемые сдачи, обратная связь, доработка и история исправлений.
- Вопросы команде, журнал, CSV, учёт презентаций проектов, отзывы о курсе и Activity.
- Уведомления и почтовая очередь; доставка требует настройки провайдера и отдельного процесса.

## Разработка

Node.js 24, PostgreSQL 16. После получения копии репозитория выполнить `npm ci`, настроить отдельную локальную БД и окружение по [инструкции разработки](docs/DEVELOPMENT.md), затем:

```sh
npm run typecheck
npm test
npm run build
```

Тесты используют только локальную `igaming_lms_test` и пересоздают её схему. Обычная рабочая строка `DATABASE_URL` тестами игнорируется. Перед любым ручным seed/HTTP-прогоном проверить целевую базу.

## Документы и структура

- [Документация](docs/README.md): архитектура, запуск, предметная модель и правила интерфейса.
- [Что осталось до запуска](docs/RELEASE-CHECKLIST.md).
- `src/` — интерфейс и сервер; `supabase/migrations/` — схема и права БД.
- `scripts/`, `tests/` — настройка и проверки; `.github/workflows/checks.yml` — CI с тестом установки и отката на одноразовом Linux, без доступа к рабочему серверу.
- `.env.example` — только шаблон. Реальные секреты, база, файлы участников, зависимости и архивы в Git не входят.

Исторические QA-отчёты и снимки остаются локально в workspace; Git включает поддерживаемую документацию. Канонический код — эта папка `app/`, отдельная от остальных материалов курса.
