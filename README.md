# Slot Design LMS

Самостоятельная LMS для курса «Слот-дизайн: от идеи до релиза». Один поток 15–25 участников: шесть воскресных занятий с 15 ноября по 20 декабря 2026 в 15:00 CET и финальный питч в январе 2027 (точная дата уточняется). Интерфейс — английский; оплата отдельно, доступ выдаёт администратор. Подгрупп, тьютора и AI-проверки нет.

**Состояние на 2 ноября 2026:** LMS размещена на Hetzner: [временный HTTPS-адрес](https://lms-135-181-197-13.nip.io/). В модуле 0 опубликованы семь исходных видео с автоматически подготовленными английскими субтитрами. На рабочем сервере проверен синтетический путь: одноразовая ссылка → обязательный пароль → модуль 0 и видео → вход по паролю. SMTP-аутентификация и получение контрольного письма подтверждены. После отдельного разрешения Александра включена автоматическая рассылка; старые QA-письма остаются отменёнными. Первое персональное приглашение доставлено, получатель вошёл и создал пароль; в Chrome открыт модуль 0. [Порядок подключения участников](docs/ONBOARDING.md); [эксплуатация и ограничения](docs/DEPLOYMENT.md). Проверка на телефоне и полная приёмка ещё впереди.

**Обновление 3 ноября 2026 установлено на рабочую LMS:** при первом создании пароля доступен изначально пустой чекбокс о раннем начале курса. При выборе сохраняются неизменяемый снимок согласия и событие для письма администраторам; запись доступна в People & course access. Галочка добровольная, зарегистрированные ранее участники не затронуты. Миграция 014 применена, рабочий выпуск — `e107eb8`. Проверены форма на HTTPS, сохранение и повтор запроса; SMTP принял контрольную отбивку владельцу. [Поведение и установка](docs/ONBOARDING.md#согласие-на-раннее-начало-курса).

## Передача и запуск на другом сервере

Начать с [инструкции получателю](docs/HANDOFF.md), затем пройти [установку на Linux](docs/SERVER-SETUP.md). В комплекте — шаблоны runtime/admin-настроек, проверка подключения, отдельные миграции, установка из Git, обновление и откат. Можно сохранить текущий Supabase или подготовить новый пустой проект. Данные и секреты передаются отдельно от Git.

## Возможности

- Вход по личной одноразовой ссылке и паролю; при первом входе пароль обязателен. Участник, назначенный эксперт и администратор.
- Материалы модулей 0–7, расписание и сроки; в модуле 0 нет глоссария. Видео MP4 и субтитры VTT хранятся в приватном бакете и открываются участнику после проверки доступа.
- Субтитры видео выключены при открытии и включаются кнопкой под плеером. Отмеченное как изученное видео размывается; «Watch again» открывает повторный просмотр, сохраняя отметку.
- Светлая тема Talentgrator использует локальные шрифты Sofia Sans Extra Condensed и Golos Text; тексты их лицензий OFL находятся в `public/fonts/`.
- Составные ДЗ 1.2–6.2, самооценки 6.1/7.1, итоговый пакет 7.2 и личный проект.
- Приватные черновики, файлы, неизменяемые сдачи, обратная связь, доработка и история исправлений.
- Вопросы команде, журнал, CSV, учёт презентаций проектов, отзывы о курсе и Activity.
- Уведомления и почтовая очередь; доставка требует настройки провайдера и отдельного процесса.

## Разработка

Node.js 24, PostgreSQL 16. После получения копии репозитория выполнить `npm ci`, настроить отдельную локальную БД и окружение по [инструкции разработки](docs/DEVELOPMENT.md), затем:

```sh
npm run typecheck
npm test
npm run build
```

Тесты используют только локальную `igaming_lms_test` и пересоздают её схему. Обычная рабочая строка `DATABASE_URL` тестами игнорируется. Перед любым ручным seed/HTTP-прогоном проверить целевую базу.

## Документы и структура

- [Документация](docs/README.md): архитектура, запуск, предметная модель и правила интерфейса.
- [Что осталось до запуска](docs/RELEASE-CHECKLIST.md).
- `src/` — интерфейс и сервер; `supabase/migrations/` — схема и права БД.
- `scripts/`, `tests/` — настройка и проверки; `.github/workflows/checks.yml` — CI с тестом установки и отката на одноразовом Linux, без доступа к рабочему серверу.
- `.env.example` — только шаблон. Реальные секреты, база, файлы участников, зависимости и архивы в Git не входят.

Исторические QA-отчёты и снимки остаются локально в workspace; Git включает поддерживаемую документацию. Канонический код — эта папка `app/`, отдельная от остальных материалов курса. Публичный репозиторий исходников: [1311-barik/slot-design-lms](https://github.com/1311-barik/slot-design-lms). Размещение в личном аккаунте временное, затем репозиторий планируется передать организации компании. Доступы к рабочему Supabase, серверу и почте в Git не входят. Не добавлять игнорируемые материалы принудительно.
