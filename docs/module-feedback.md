# Короткий отзыв перед работой в модуле 2

Решение Александра от 23 ноября 2026: в понедельник после занятия запросить короткий фидбек внутри LMS и открывать модуль 2 после отправки. Для первого запроса отдельно назначено 23 ноября, 15:00:35 Europe/Lisbon («через 45 минут»). Раньше этого времени включать запрос нельзя.

Миграция 019 создаёт настройку только для модуля 2. Обычное время — следующий понедельник после занятия, 09:00 Europe/Lisbon, из текущей даты занятия в `lms.sessions`; для первого запуска применяется дополнительная нижняя граница выше. Время хранится в `lms.module_feedback_prompts.request_after`, не зависит от часового пояса браузера. Остальные модули не включаются автоматически.

Один именной комментарий; оценка 1–5 необязательна. Любой содержательный отзыв о модуле 2, включая ранее отправленный и отрицательный, открывает доступ; общий отзыв о курсе его не заменяет. Ответы видят автор и администраторы. Прямые запросы к материалам, видео, заданиям, вопросам и сохранённым версиям ограничены RLS до отзыва; существующие данные не удаляются. Приватные собственные загрузки остаются собственностью участника.

Уведомление `feedback.requested` имеет `channel=in_app`: оно сразу получает внутренний статус доставки и не попадает в SMTP-очередь или экран Email. Даже ручное изменение статуса не разрешает отправку такого уведомления по email. Планирует существующий почтовый worker, а также загрузка workspace после наступления срока; при простое запрос появляется после восстановления, без истечения окна. Повторы не создают дубли благодаря ключу «модуль + участник». После ответа запрос отмечается прочитанным. Пользователи без действующего доступа и сотрудники не получают запрос; активные QA-профили должны быть исключены при проверке рабочего списка до активации.

При открытом кабинете данные обновляются раз в минуту и при возвращении в окно, если нет несохранённого текста. На модуле 2 показана форма вместо учебных действий; на других страницах — приглашение перейти к форме. Разрешение браузера на системные push-уведомления не требуется.

## Полный предпросмотр кабинета участника — 23 ноября 2026

Решение Александра: `View as student` должен показывать весь интерфейс участника, включая все уведомления и новые функции. Предпросмотр больше не собирается из административных данных с пустыми массивами: администратор выбирает действующего участника, и сервер читает его обычный workspace с теми же RLS-ограничениями. Используется тот же компонент кабинета. Видны собственные черновики, отправленные работы, решения, вопросы, отзывы, прогресс, проект, уведомления, обязательные формы, согласие и создание пароля. Если выбранный участник уже дал отзыв, повторная обязательная форма не показывается — ровно как при его обычном входе.

Это явно обозначенный просмотр выбранного участника. Он открывает администратору в том числе приватные черновики и их вложения только через отдельный проверяемый маршрут предпросмотра; обычные административные запросы сохраняют прежние права. Выбор участника хранится в URL; ссылки из уведомлений, видео, субтитры и скачивание файлов сохраняют этот контекст. История уведомлений участника больше не обрезается до 30/50 записей.

Сессия администратора не меняется. Изменяющие запросы с `preview=student` отклоняются сервером до выполнения; формы и отметки прочтения показаны с отключённым сохранением. Сам просмотр не планирует уведомления и не отправляет письма. Возврат в администратора сохраняет его сессию. Новые функции должны использовать тот же кабинет и маршрут API без отдельных условий, скрывающих их в предпросмотре. Проверка новой функции включает обычного участника и предпросмотр того же участника.

Проверки: `tests/student-preview.test.ts` — сохранение выбранного участника в ссылках; `tests/student-preview-access.test.ts` — реальные транзакции, соответствие данных и ограничения выбора; `tests/student-preview.integration.ts` — HTTP, согласие/пароль, весь workspace, 56 уведомлений, закрытый модуль 2, приватный файл, запрет любых POST и неизменность сессии. Последний прогон включён в существующий CI HTTP-этап. Подготовленные тесты не означают успешного прогона или установки: фактический статус указывается отдельно.
