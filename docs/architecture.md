# Архитектура LMS

Актуализировано 1 ноября 2026 при подготовке отдельного репозитория. Это описание реализованной сборки, а не полная приёмка ТЗ. [Условия запуска](RELEASE-CHECKLIST.md).

## Компоненты

Next.js 16.4.3, React 19.2.8 и TypeScript. Один процесс обслуживает интерфейс и API; почтовый обработчик запускается отдельно. Приложение размещено на Hetzner за nginx и HTTPS; [эксплуатация](DEPLOYMENT.md). Версии зависимостей закреплены в lockfile.

Рабочие PostgreSQL/Auth/Storage — Supabase. Локально — отдельная PostgreSQL 16 и синтетические аккаунты. Режим Supabase не переключается автоматически на тестовый вход. Схема `lms` не должна входить в exposed schemas Data API: браузер работает через сервер LMS.

- `src/lib/auth.ts`, `supabase-admin.ts` — вход, сессии, пароль и приглашения.
- `src/lib/service.ts` — команды, переходы состояний и комплектность работ.
- `src/lib/db.ts` — транзакции, `lms_runtime`, контекст проверенного участника.
- `src/lib/contract.ts`, `course.ts` — форматы команд и состав заданий.
- `src/lib/files.ts`, `file-validation.ts` — приватное хранение, права и проверка вложений.
- `src/lib/mail.ts`, `scripts/mail-worker.ts` — планирование и доставка уведомлений.
- `src/app/api/v1/[...path]/route.ts` — HTTP, CSRF, лимиты и безопасные ошибки.
- `src/app/workspace.tsx` — кабинеты участника, эксперта и администратора.

## Данные и права

Доменная транзакция устанавливает `lms_runtime` и actor; RLS ограничивает чтение/изменение. Эксперт имеет доступ по назначению на задание. Рабочее подключение `lms_backend` отделено от миграций: без BYPASSRLS, владения схемой и доступа к паролям Auth; прямые права входа и почты перечислены в миграции 013.

Черновик приватен. Сдача создаёт неизменяемый снимок; доработка — новый черновик. Команды сериализуются по actor и блокируют работу, ревизии защищают от перезаписи, ключи идемпотентности предотвращают дубли. Отзывы и исправления сохраняются в истории; старое решение не меняет статус новой версии. Черновик отзыва эксперта содержит автора, ревизию и основание исправления.

Миграции 001–016 включают проекты, состав итогового пакета, вопросы/ответы, материалы, занятия, сроки, журнал, презентации, уведомления, отзывы о курсе, серверную роль и согласие на раннее начало курса. Они применяются последовательно из `supabase/migrations/`. Локальный seed отделён от настройки Supabase. Миграция 014 добавляет доказательство согласия, 015 — источник позднего подтверждения, 016 — снимок ссылки и SHA-256 показанного PDF.

### Согласие при регистрации и в кабинете — 3 ноября 2026

`src/lib/early-commencement.ts` задаёт общий для формы и сервера английский текст, курс и версию. API `auth/password` принимает логическое `earlyCommencementConsent` и строку `consentVersion`; имя, email, дата и текст из браузера не принимаются. При `true` сервер требует актуальную версию. Пропуск/`false` не создают запись. Смена пароля не используется для позднего согласия. Отдельный API `auth/early-commencement` принимает только `earlyCommencementConsent: true` и текущую `consentVersion`; идентичность и снимок берутся на сервере. Доступен только действующему зарегистрированному участнику. Повтор первоначального запроса с существующей записью безопасен.

Миграция 014 добавляет `early_commencement_consents` с уникальностью по участнику и курсу, неизменяемостью и RLS для автора/администратора. Время и источник формирует БД; runtime не может подставить свою дату. Backend читает записи для почтового обработчика, но не меняет и не удаляет их. Завершение регистрации и outbox фиксируются вместе с согласием. Supabase Auth не участвует в транзакции PostgreSQL; повтор первого сохранения того же пароля допускается после сбоя БД. Обычная смена пароля сохраняет исходную дату первого создания пароля.

По последнему уточнению Александра от 3 ноября согласие обязательно для допуска к курсу. Пустой чекбокс и ссылка на PDF видны до входа. После проверки личности UI отправляет выбранное согласие отдельным запросом. Если записи нет, GET workspace отдаёт только профиль и `consentRequired`, а все API курса, включая файлы, видео, загрузки и команды, закрыты 403 `consent_required`. Участник видит только экран подтверждения. Это же ограничение действует при входе через кнопку команды; сотрудники определяются серверной ролью и согласие участника не дают. До первого пароля сохраняется `lms_registration`, после — `lms_account`. Запись и outbox атомарны; пароль и исходная дата регистрации не меняются.

Версия согласия `2026-11-03.2` фиксирует подключение PDF, переданного пользователем. Дословный текст согласия сохранён. Файл опубликован с именем, включающим дату редакции и SHA-256, и доступен без входа. Новые записи сохраняют его URL, полный SHA-256 и дату редакции; старые записи не дополняются задним числом. Отбивка и административный просмотр показывают привязанный документ. Изменять байты существующего PDF по тому же имени нельзя.

`consent.early_commencement` создаёт по одному уведомлению каждому действующему администратору, используя снимок из записи. Письмо содержит оригинальный текст и источник; доставка и повторные попытки используют существующую очередь. Первый выпуск установлен на Hetzner в выпуске `e107eb8` 3 ноября; подтверждены запись через рабочий API и SMTP-отправка контрольной отбивки владельцу.

## Файлы

Все файлы выдаются через сервер с проверкой доступа; бакет Supabase приватный. Формат, сигнатура, лимиты, UTF-8 и офисный контейнер проверяются до регистрации. Изображения декодируются через `sharp`. Это не антивирусная проверка; полноценный карантин и фоновые операции очистки остаются в требованиях. Уже скачанные байты отозвать нельзя.

## Почта

События записываются в outbox вместе с доменной операцией. Обработчик формирует задания и перепроверяет актуальность перед доставкой. Первое приглашение и повторный вход получают одноразовую ссылку от Supabase Auth непосредственно перед отправкой через SMTP LMS; токен не хранится в очереди. Поддерживаются локальные файлы писем, Brevo и SMTP; реальные учётные данные не входят в Git. Неизвестный результат доставки не должен порождать слепой повтор.

## Проверка и эксплуатация

Проверяются публичные команды, реальные транзакции/RLS, HTTP и браузер. CI использует одноразовую локальную PostgreSQL и синтетические данные. Локальный Pass не заменяет проверку целевого Supabase, реальной почты, телефона/Safari и восстановления резервной копии. Отправка рабочих писем, миграции Supabase и размещение на Hetzner не выполняются самим CI.
